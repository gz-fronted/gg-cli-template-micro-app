# 产品需求与业务边界规范

## 依据优先级

当产品文档、接口文档和 UI 视觉稿存在差异时，默认按以下优先级判断：

```text
产品文档 > 接口文档 > UI 视觉稿
```

- 产品文档决定功能范围、业务流程、状态、权限、交互限制和验收标准。
- 接口文档决定请求地址、Method、参数、响应字段、类型、枚举和错误码。
- UI 视觉稿决定布局、尺寸、间距、颜色、字号、对齐和视觉状态。

发现冲突时必须明确列出差异和待确认事项，不得选择更容易实现的一方。

## 禁止擅自补充业务定义

- 产品文档未定义的状态、枚举、按钮、交互和动效不得自行补充。
- UI 稿出现但产品文档未说明的业务含义必须先确认。
- 通用经验只能用于技术实现，不能替代业务定义。
- Mock 数据必须严格覆盖已确认状态，不得为了丰富场景虚构业务状态。

## 接口文档与 Mock

获得接口文档后，应默认同步生成对应的声明式 Mock 配置和代表性数据，不要求开发者
学习或手写 MSW Worker、Handler、HttpResponse 等实现细节。

仅在以下情况询问：

- 产品语义或枚举含义无法确认。
- 多个接口之间的状态关联无法从文档判断。
- 字段示例涉及敏感数据或真实账号。
- 错误场景、分页边界或文件下载协议未定义。

能够从产品和接口文档确定的内容应直接实现，不得把机械性 Mock 编写工作转交给开发者。
